# SeatSync Sprint 0 — Foundation Implementation Plan
## Decisions, MUST/MUST NOT Rules & Windows (win32) Notes
- **API Framework Decision:** Use **Express** (`express` + TypeScript + `zod`); simplest option permitted by doc ("Express (or NestJS)") matching `apps/api/src/{routes,services,db}` layout.
- **MUST / MUST NOT Rules:** TS `strict: true` (no `any` in `db`/`services`); hand-written SQL only via `pg` & `node-pg-migrate` (no ORM); test against real Compose Postgres (never mock DB); Redis optional for correctness (log & degrade gracefully if down); all 15 Config-table tunables read from env via `apps/api/src/config.ts` (no hardcoded tunables); money as integer paise. **Out of scope:** auth and any table other than `users`.
- **Windows (`win32`) Notes:** Use `curl.exe` (not PowerShell `curl` alias `Invoke-WebRequest`); in PowerShell 5.1 replace `&&` with `; if ($?) { ... }` or run via `cmd /c`; copy env with `Copy-Item .env.example .env`; commit `.gitattributes` (`* text=auto eol=lf`) so Linux Docker containers receive LF; use `dotenv`/`cross-env` in pnpm scripts for cross-platform env loading.

## Ordered Implementation Steps (Single-Coder-Run Granularity)
### Step 1: Repo Bootstrap, Monorepo Workspace & Strict Tooling

- **Details:** Run `git init -b main`, initial commit (`docs` + `.gitignore`/`.gitattributes`), then `git checkout -b sprint-0-foundation`. Configure pnpm workspace (`apps/*`, `packages/*`), strict TS (`strict: true`), ESLint + Prettier, and root scripts `lint`, `typecheck`, `test` (`pnpm -r`). Export shared `zod` health response schema from `packages/shared`; scaffold minimal Next.js 14/15 TS App Router page in `apps/web`.
- **Verify & Acceptance Criteria:** `git branch --show-current` is `sprint-0-foundation`; `pnpm install`, `pnpm lint`, and `pnpm typecheck` all exit 0. (Covers AC #4 lint/typecheck).

### Step 2: Docker Compose Stack, `.env.example` & Fail-Fast Typed Config Loader
- **Files:** `.env.example`, `.dockerignore`, `docker-compose.yml`, `apps/api/Dockerfile`, `apps/web/Dockerfile`, `apps/api/src/config.ts`, `apps/api/test/config.test.ts`.
- **Details:** `.env.example` defines all 15 Config-table variables (`DATABASE_URL`, `REDIS_URL`, `DB_POOL_SIZE=20`, `JWT_SECRET`, `ACCESS_TOKEN_TTL_SECONDS=900`, `REFRESH_TOKEN_TTL_SECONDS=1209600`, `HOLD_TTL_SECONDS=600`, `SWEEPER_INTERVAL_SECONDS=30`, `MAX_SEATS_PER_HOLD=6`, `PAYMENT_PROVIDER=fake`, `PAYMENT_WEBHOOK_SECRET`, `HOLDS_RATE_LIMIT_PER_MINUTE=20`, `CORS_ORIGINS=http://localhost:3000`, `LIVE_UPDATE_MAX_MS=1000`, `RETENTION_DAYS=30`). `apps/api/src/config.ts` exports `loadConfig(env = process.env)` validated with `zod`, applying table defaults and throwing immediately on missing required vars (`DATABASE_URL`, `REDIS_URL`, `JWT_SECRET`, `PAYMENT_WEBHOOK_SECRET`). `docker-compose.yml` defines `db` (`postgres:16`, port 5432, healthcheck), `redis` (`redis:7`, port 6379, healthcheck), `api` (port 4000), and `web` (port 3000).
- **Verify & Acceptance Criteria:** `Copy-Item .env.example .env`; `pnpm --filter api test -- config.test.ts` passes (verifies fail-fast on missing required vars & default parsing); `docker compose up -d db redis` starts healthy containers. (Covers Config task & AC #1/#4 setup).

### Step 3: `node-pg-migrate` Setup & First Migration (`users` Table Only)
- **Files:** `apps/api/migrations/001_create_users.js` (or `.sql` via `node-pg-migrate`), `apps/api/package.json` (`migrate` script).
- **Details:** Configure `node-pg-migrate` reading `DATABASE_URL` and `apps/api/migrations`. Migration `up` executes raw SQL creating `users` (`id UUID PRIMARY KEY DEFAULT gen_random_uuid()`, `email TEXT NOT NULL UNIQUE`, `password_hash TEXT NOT NULL`, `role TEXT NOT NULL CHECK (role IN ('ORGANIZER', 'ATTENDEE'))`, `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`); `down` runs `DROP TABLE IF EXISTS users;`. Add `pnpm --filter api migrate up` and `pnpm --filter api migrate down`.
- **Verify & Acceptance Criteria:** Against running `db` container, `pnpm --filter api migrate up`, `pnpm --filter api migrate down`, and `pnpm --filter api migrate up` each exit 0. (Covers AC #3).

### Step 4: Express App, PG Pool, Redis Client, Pino `X-Request-Id` & `GET /health`
- **Files:** `apps/api/src/db/pool.ts`, `apps/api/src/redis/client.ts`, `apps/api/src/logger.ts`, `apps/api/src/middleware/requestId.ts`, `apps/api/src/routes/health.ts`, `apps/api/src/app.ts`, `apps/api/src/server.ts`.
- **Details:** `pool.ts` creates `pg.Pool` (`connectionString: config.DATABASE_URL`, `max: config.DB_POOL_SIZE`). `redis/client.ts` creates an `ioredis` client with `lazyConnect`/`enableOfflineQueue: false` and error listener so Redis downtime never crashes the API. `requestId.ts` uses incoming `x-request-id` or `crypto.randomUUID()`, sets `X-Request-Id` header, and attaches a child `pino` logger (`req.log`) so every log line includes `requestId`. `GET /health` pings Postgres (`SELECT 1`) and Redis (`PING`): returns `200 {"db":"ok","redis":"ok"}` if both pass, or `503` (e.g. `{"db":"ok","redis":"down"}`) naming any failing dependency.
- **Verify & Acceptance Criteria:** `docker compose up -d --build`; `curl.exe -s http://localhost:4000/health` returns `{"db":"ok","redis":"ok"}`; `docker compose stop redis` then `curl.exe -i http://localhost:4000/health` returns 503 naming `"redis"` with `X-Request-Id` header; `docker compose start redis`. (Covers AC #1 & AC #2).

### Step 5: Jest + Supertest Integration Tests & Truncate-Between-Tests Helper
- **Files:** `apps/api/jest.config.ts`, `apps/api/test/helpers/db.ts`, `apps/api/test/health.test.ts`.
- **Details:** Configure Jest (`ts-jest`, `--runInBand`) against real Compose Postgres. `test/helpers/db.ts` provides `truncateAll(pool)` (`TRUNCATE TABLE users RESTART IDENTITY CASCADE` / dynamic public table truncate excluding `pgmigrations`). `test/health.test.ts` tests via Supertest: (1) `GET /health` returns 200 `{"db":"ok","redis":"ok"}` and echoes/generates `X-Request-Id` against real Postgres + Redis; (2) when passed a closed/unreachable Redis client (while still using real Postgres, zero DB mocks), `GET /health` returns 503 naming `redis`; (3) inserting a `users` row and running `truncateAll` leaves 0 rows.
- **Verify & Acceptance Criteria:** `pnpm --filter api test` and root `pnpm lint && pnpm typecheck && pnpm test` exit 0. (Covers AC #2 & AC #4).

### Step 6: GitHub Actions CI Workflow & README
- **Files:** `.github/workflows/ci.yml`, `README.md`.
- **Details:** `.github/workflows/ci.yml` runs on `push`/`pull_request` with `postgres:16` and `redis:7` service containers, sets Config env vars, and runs `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm typecheck`, `pnpm --filter api migrate up`, `pnpm --filter api migrate down`, `pnpm --filter api migrate up`, and `pnpm test`. `README.md` documents prerequisites, Windows setup (`Copy-Item .env.example .env`, `curl.exe`), and standard commands.
- **Verify & Acceptance Criteria:** Full local CI sequence (`pnpm lint`, `pnpm typecheck`, `migrate up/down/up`, `pnpm test`) exits 0. (Covers AC #5 locally).
## Final Verification Mapping & Ambiguities/Risks
- **AC1 (`200 {"db":"ok","redis":"ok"}`):** `docker compose up -d --build` then `curl.exe -s http://localhost:4000/health` | **AC2 (503 naming `redis`):** `docker compose stop redis` then `curl.exe -i http://localhost:4000/health` (plus `apps/api/test/health.test.ts`) | **AC3 (migrations):** `pnpm --filter api migrate up` then `pnpm --filter api migrate down` (and `migrate up` again before tests) | **AC4 (quality gate):** `pnpm lint`, `pnpm typecheck`, `pnpm test` all exit 0 | **AC5 (CI on PR — Blocked/Human):** No git remote exists yet; pushing branch `sprint-0-foundation` and opening a GitHub PR to verify `.github/workflows/ci.yml` on GitHub Actions requires a human-configured remote repository.
- **Risks:** Docker Desktop must be running on Windows host; `api` container in `docker-compose.yml` must use service hostnames (`db:5432`, `redis:6379`) while host CLI tests/migrations use `localhost:5432` and `localhost:6379` from `.env`.
